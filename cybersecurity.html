Step 18 · Cybersecurity case

SQL injection: how it happens and how to prevent it

A basic case study of one of the most common web vulnerabilities, written from a defensive point of view for developers who build PHP and database applications.

CybersecurityAI literacyTechnical interviewMock interview

01 · The case

Five questions, answered

Scope. This case study is about understanding and defence. The demo below never connects to a database, and security testing should only be done on systems I own or have written permission to test.
01

What is the vulnerability?

SQL injection (SQLi) happens when an application builds a database query by joining user input directly into the SQL text. The database cannot tell which part is the developer's code and which part is the user's data, so a crafted input can change what the query does.

It belongs to the Injection category of the OWASP Top 10, a widely used list of the most serious web application risks.

02

How can it happen?

It usually starts with a login form, search box, or URL parameter whose value is placed straight into a query. This is the classic mistake in PHP:

// Vulnerable: input is joined into the SQL text
$sql = "SELECT * FROM users WHERE username = '" . $_POST['username'] . "' AND password = '" . $_POST['password'] . "'";
$result = mysqli_query($conn, $sql);

If the username contains a single quote, the quote closes the text early and the rest of the input is read as SQL. Try it below. Nothing here touches a database; it only shows how the query text changes.

Attackers use this to skip a login check, read data from other tables, or change and delete records.





03


What are the risks?


    

  • Unauthorised access: bypassing a login and reaching accounts or admin pages.
    • 

  • Data exposure: customer details, order history, and password hashes can be read.
    • 

  • Data loss or tampering: records can be changed or deleted, so the data can no longer be trusted.
    • 

  • Wider compromise: stolen credentials and server details can be used to attack other systems.
    • 

  • Business and legal impact: downtime, lost customer trust, and duties under the Data Privacy Act of 2012 (RA 10173) when personal data is exposed.
    • 



For any online shop, including projects like Lunar Moon Jewelry, customer and order records are exactly what would be at risk.





04


How can developers prevent it?


The main fix is to keep input as data by using prepared statements (parameterised queries):


// Safer: placeholders keep input as data, not SQL
$stmt = $pdo->prepare("SELECT id, password_hash FROM users WHERE username = :u");
$stmt->execute([':u' => $_POST['username']]);
$user = $stmt->fetch();
if ($user && password_verify($_POST['password'], $user['password_hash'])) {
    // log the user in
}


    

  • Use prepared statements with PDO or MySQLi for every query that includes input.
    • 

  • Validate input on the server: type, length, format, and allowed values.
    • 

  • Store passwords with password_hash() and check them with password_verify().
    • 

  • Give the database account only the permissions the app needs.
    • 

  • Show generic error messages to users and keep detailed errors in server logs.
    • 






05


What security practices should be implemented?


    

  • Defence in depth: combine validation, prepared statements, least privilege, and monitoring so one failure is not enough.
    • 

  • Code review: check every place user input reaches a query.
    • 

  • Keep software updated: PHP, the database, frameworks, and libraries.
    • 

  • Protect traffic and sessions: HTTPS and secure cookies (HttpOnly, Secure, SameSite).
    • 

  • Log and monitor: watch for repeated failures and unusual requests.
    • 

  • Back up data regularly and test the restore.
    • 

  • Test responsibly: only on my own projects or with permission.
    • 



Seminars such as AI in Cybersecurity (August 8, 2026) and Digital Fortify (November 24, 2023) helped me see why these habits matter.









02 · Takeaway


Lesson learned


Never trust input. Treat everything that comes from a user as data, and let the database driver handle it with placeholders.
